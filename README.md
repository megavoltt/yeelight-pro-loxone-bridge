# Yeelight Pro ↔ Loxone Bridge

Мост между шлюзом **Yeelight Pro** (S20, BLE Mesh) и **Loxone Miniserver**:
управление светильниками, яркостью и цветовой температурой (CCT 2700–6500 К)
из Loxone Config, приложения Loxone и автоматики.

Мост — это Python-демон, который ставится на контроллер **Wiren Board** в той же
локальной сети. Он держит TCP-сессию с шлюзом Yeelight Pro по официальному
LAN-протоколу, пересылает состояния устройств на Miniserver по UDP
(VirtualInUdp), принимает команды от Miniserver (VirtualOut HTTP) и поднимает
веб-интерфейс со статусом, настройками и **выгрузкой шаблонов Loxone Config**.

## Возможности

- Включение/выключение, яркость (0–100 %), цветовая температура (2700–6500 К
  или в процентах 0–100 %).
- Статусы в Loxone в реальном времени: питание, яркость, температура,
  доступность узла (online/offline).
- Автоматическое обнаружение устройств в топологии шлюза; новые светильники
  появляются на веб-странице и в шаблонах сами.
- Веб-интерфейс: статус соединения, живые параметры узлов, тестовые команды,
  настройка без правки файлов, выгрузка шаблонов Loxone (по устройству,
  общие, ZIP со всеми).
- Генерация шаблонов в формате, проверенном на живых Config: все входы
  аналоговые (`templateType="1"`), выходы HTTP с `CmdOn`/`CmdOff`
  (`templateType="3"`).
- Переподключение к шлюзу с нарастающим интервалом, контрольный опрос
  состояния каждые 30 с, переживает перезагрузки контроллера и Miniserver'а.
- Только стандартная библиотека Python 3 — никаких зависимостей.

## Архитектура

```
 Yeelight Pro шлюз (S20)                 Wiren Board                        Loxone Miniserver Gen 2
 192.168.1.53                            192.168.1.62                       192.168.1.91

  TCP 65443 <------------- JSON-кадры (CRLF) ------------- yeelight_bridge.py (systemd)
  пуши gateway_post.prop                                  - слушает UDP 7002 (команды)
  (p / l / ct / o)                                        - шлёт UDP 7002 (статусы) ----> VirtualInUdp
                                                          - HTTP :8082 (веб + /set) <-- VirtualOut HTTP
```

Формат обмена с мостом (оба канала эквивалентны):

```
UDP  датаграмма:   yeelight.<узел>.<параметр>=<значение>   -> 192.168.1.62:7002
HTTP запрос:       GET http://192.168.1.62:8082/set/<узел>/<параметр>/<значение>
```

| Параметр | Значение | Направление | Описание |
|---|---|---|---|
| `p` | 0/1 | оба | питание светильника |
| `l` | 0–100 % | оба | яркость (`l=0` эквивалентно выключению) |
| `ct` | 2700–6500 | оба | цветовая температура, кельвины |
| `ctp` | 0–100 % | команда | температура в процентах (0 = 2700 К … 100 = 6500 К) |
| `sww` | составной код | команда | Smart Actuator WW или Lumitech DMX: яркость и CCT одним значением от выхода LC |
| `o` | 0/1 | статус | узел доступен в шлюзе |
| `N-p` | 0/1 | оба | канал N виртуального устройства шлюза |

## Требования

- Контроллер Wiren Board (WB6/WB7/WB8) с прошивкой, где есть `python3`
  (все актуальные релизы).
- Шлюз Yeelight Pro (S20) в той же сети, с подключёнными устройствами.
- Loxone Miniserver (проверено на Gen 2, Config 17.2; нужны виртуальные
  входы UDP и виртуальные выходы HTTP).

## Установка на Wiren Board

```bash
# с компьютера: копируем два файла в /root на контроллере
scp yeelight_bridge.py install.sh root@<IP контроллера>:/root/

# на контроллере:
ssh root@<IP контроллера>
sh install.sh
```

Скрипт создаёт `/mnt/data/yeelight-bridge/` (переживает обновления прошивки),
конфиг по умолчанию, systemd-юнит `yeelight-bridge` с автозапуском и проверяет,
что сервис поднялся. Повторный запуск обновляет только демон.

## Настройка

Откройте **http://\<IP контроллера\>:8082/** и укажите:

| Параметр | По умолчанию | Что это |
|---|---|---|
| IP шлюза Yeelight | 192.168.1.53 | адрес шлюза S20 в LAN |
| Порт TCP шлюза | 65443 | порт LAN-протокола |
| IP Miniserver | 192.168.1.91 | куда слать статусы (UDP) |
| Порт статусов | 7002 | порт VirtualInUdp на Miniserver'е |
| Порт команд | 7002 | UDP-порт моста для датаграмм |
| Порт веба | 8082 | HTTP: страница и `/set` |
| Опрос шлюза | 30 с | период полной пересылки состояний |
| Переход l/ct | 500 мс | плавность изменений |
| CCT мин/макс | 2700 / 6500 | диапазон цветовой температуры |
| Алиасы узлов | `id=alias` | свои имена устройств в командах |
| Ключ | пусто | если задан, `/set/<ключ>/…` требует его |

«Сохранить и перезапустить» пишет `config.json` и перезапускает сервис
(~5 с, systemd поднимает сам). Веб-страница без авторизации — используйте
только в локальной сети.

## Шаблоны Loxone Config

На веб-странице, в секции **«Шаблоны Loxone»**:

- у каждого устройства — кнопки **VIU** и **VO** (отдельный XML);
- сверху — **VIU/VO всех устройств** одним блоком и **ZIP со всеми шаблонами**;
- новые устройства шлюза появляются сами.

Импорт: **Периферия → Виртуальные входы → «Импорт шаблона»** (VIU), затем
**Периферия → Виртуальные выходы → «Импорт шаблона»** (VO). После импорта —
**сохранить в Miniserver**.

Заголовки команд — на русском («Вкл/выкл», «Яркость», «Цветовая температура»,
«Канал 1»…), машинные имена — в поле Comment.

## Монтаж в Config

### Lighting Controller → Lumitech DMX (для виртуального светильника)

Для одновременного управления яркостью и цветовой температурой одним световым
контуром:

1. В блоке **Lighting Controller** назначьте контуру тип **Lumitech DMX**.
2. Установите **MinCt = 2700 К** и **MaxCt = 6500 К** — те же границы, что в мосте.
3. Подключите нужный выход **LC** напрямую к аналоговой VO-команде
   **«Smart WW (яркость + CCT) — …»**. «Аналоговая память» не нужна. Отдельные
   команды `p`, `l` и `ct` для этого контура не подключайте.

Мост принимает два составных формата от Lighting Controller:

- **Lumitech DMX:** `R + G*1000 + B*1000000`, компоненты 0–100. Яркость равна
  наибольшему компоненту, CCT определяется соотношением `R/(R+B)`. Например,
  `29029029` = 29 % и 4600 К; `100100` = 100 % и 2700 К; `100000000` = 100 % и 6500 К.
- **Smart Actuator WW:** префикс `20`, яркость тремя цифрами (`000`…`100`), затем
  CCT в кельвинах. Например, `201002700` = 100 % и 2700 К, `200504000` = 50 % и
  4000 К. Этот формат поддерживается для совместимости со штатными устройствами
  Loxone и интеграциями Hue, но при ручном подключении виртуального выхода
  рекомендуется Lumitech DMX.

Значение `0` выключает светильник. Мост декодирует оба формата и отправляет в шлюз
один `gateway_set.prop` с полями `p`, `l` и `ct`, поэтому яркость и температура
применяются одновременно. Команда: `/set/lamp/sww/<v>` или UDP
`yeelight.lamp.sww=<v>`.

### Раздельное управление (альтернатива)

Яркость и питание — блок **«Диммер»**, выход **AQ** → команда «Яркость — …».
Выключение слайдером в **0** само отправляет `p=0`.

Цветовая температура — второй блок **«Диммер»**, выход **AQ** → команда
«Цветовая температура, % — …» (`ctp`) либо «Цветовая температура — …» (`ct`).
Этот вариант требует двух контуров и не нужен при подключении составного выхода LC.

Статусы (необязательно) — входы VIU на блоки «Только информация»; аналоговые
0/1 свободно подключаются и к цифровым входам блоков.

> Ограничение самого Loxone: блоки «Диммер»/LightControllerV2 не принимают
> внешний статус нагрузки — изменения из приложения Yeelight отображаются
> в информационных блоках, не двигая слайдеры. Если лампу обесточить
> настенным выключателем, придёт `o=0` (offline), а `p` замрёт на последнем
> значении.

## Команды вручную / из скриптов

```bash
# включить / выключить (эквивалентно l=1 / l=0)
curl http://192.168.1.62:8082/set/lamp/p/1
curl http://192.168.1.62:8082/set/lamp/p/0

# яркость 50 %, температура 4000 К, теплота 25 %
curl http://192.168.1.62:8082/set/lamp/l/50
curl http://192.168.1.62:8082/set/lamp/ct/4000
curl http://192.168.1.62:8082/set/lamp/ctp/25

# одна команда Smart WW: включить, 50 %, 4000 К; затем выключить
curl http://192.168.1.62:8082/set/lamp/sww/200504000
curl http://192.168.1.62:8082/set/lamp/sww/0

# то же самое по UDP
printf 'yeelight.lamp.ct=4000' | nc -u -w1 192.168.1.62 7002
printf 'yeelight.lamp.sww=200504000' | nc -u -w1 192.168.1.62 7002
```

## Протокол шлюза Yeelight Pro (справка)

- Discovery: UDP-бродкаст `YEELIGHT_GATEWAY_CONTROL_DISCOVER` на порт 1982 →
  ответ `pid/mac/did/ip`.
- Сессия: TCP 65443, JSON-кадры через `\r\n`, без авторизации в LAN.
- Запросы: `gateway_get.topology`, `gateway_get.node {"id":N}`.
- Команды: `gateway_set.prop`,
  `nodes:[{"id":N,"nt":2,"duration":мс,"set":{...}}]`.
- Пуши состояния: `gateway_post.prop` — приходят сами по любым изменениям,
  включая управление из приложения Yeelight Pro.

Опубликованная спецификация — интеграция Home Assistant
[Yeelight/ha_yeelight_pro](https://github.com/Yeelight/ha_yeelight_pro)
(`lan_contract.py`, `lan_methods.py`).

## Отладка

```bash
journalctl -u yeelight-bridge -f      # журнал на контроллере
systemctl restart yeelight-bridge     # перезапуск
```

Окно истины — веб-страница моста: если значение правильное там, но не в Loxone
— проблема в приёме на Miniserver'е; если неверно уже на странице — в канале
мост ↔ шлюз.
